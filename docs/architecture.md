# 実装メモ

GitHub Pages に置いた静的ファイルだけで動きます。サーバーもビルドもありません。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | 画面の骨格（マークアップ） |
| `styles.css` | 画面のスタイル |
| `app.js` | 画面まわりの JavaScript（地図の初期化・表・ナウキャストのタイムライン・フルスクリーンなど） |
| `msm.js` | 雲量の地図。`.om` ファイルの読み込みと、Leaflet への描画 |
| `nowcast.js` | 降水・雷ナウキャストのタイルと地点サンプリング |
| `pin.js` | 地点ピン（置く・動かす・同期）と場所検索、緯度経度の読み取り |
| `places.js` | 保存地点（localStorage の読み書き、地図上の水色の丸、登録・編集・削除 UI） |
| `weather.js` | 地点の予測値と気象庁の週間予報の取得、天気コードの対応表 |
| `colors.js` | 地図の配色定数（凡例と描画で共有） |
| `sw.js` | Service Worker（PWA インストール用。本体はネットワーク優先） |
| `docs/legend.svg` | README に載せる色の凡例（手で編集せず、作り直す） |

外部ライブラリは CDN から読み込みます（Leaflet、SunCalc、`@openmeteo/file-reader`）。`@openmeteo/file-reader` は README に「本番向けではない」と書かれているため、`index.html` の import map で版を固定しています。

## 雲量の地図（`msm.js`）

- Open-Meteo の S3 にある MSM の `.om` ファイルを**1コマぶん丸ごと**取得します（全要素で約800KB、1リクエスト）。範囲指定で雲量だけ読むと転送量は1/4になりますが、往復が二十数回に増えて3倍以上遅くなるため、丸ごと取得にしています。
- 格子は緯度22.4〜47.6°（0.05°刻み、505行）、経度120〜150°（0.0625°刻み、481列）。**行0が南端**です。
- 描画は `L.GridLayer` を継承した `CloudGridLayer`。タイルの各画素の緯度経度から**最も近い格子**の値を引いて塗ります。補間や平滑化はしません（加工と見なされないため）。
- 色は20%未満が透明、20/40/60/80/100%で5段階。黒い下地に重ねるので、多いほど白く濃くなります。濃さはアルファで表すので、レイヤー自体は不透明のまま重ねます。区切りはウェザーニューズの雲量タイルと同じで、色だけを下地に合わせて反転させたものです。
- 下地は国土地理院の陰影起伏図（CSS で暗く落とす）と白地図（階調反転して輪郭線だけを白く残す）の2枚。地名などの文字情報を減らし、無彩色にして雲量の色と競合しないようにしています。フィルタが雲量レイヤーに掛からないよう、下地は専用ペイン（z-index 199）に分けています。どちらのタイルも海域が透過なので、そのペインの背景色が海の色になります。
- 4枚の地図（全雲量・上層・中層・下層）は同じフレームのデータを共有し、位置とズームを連動させます。

## 風の地図（`msm.js` の `WindGridLayer`）

- 同じ `.om` の `wind_u_component_10m` / `wind_v_component_10m` を使うので、雲量のための取得に乗せて通信量は増えません。
- **流線・パーティクルは採らない。**格子点の間を補間する必要があり、雲量を最近傍で描いているのと同じ理由（空間内挿は独自の予報とみなされうる）で使えません。採るのは風速の面塗り＋間引いた矢印です。
- **間引きは補間ではない。**実在する格子点の部分集合を見せるだけで、存在しない中間値は作りません。画面上の矢印間隔がおおよそ一定になるよう、ズームから段数を決めます。
- 配色は表の「強いほど濃い緑」を黒地図に持ち込まず、気象庁の降水に倣った寒色→暖色（10 m/s で色相が切り替わる）。表と地図で色が違うのは雲量と同様、下地の明暗に合わせた意図的な食い違いです。
- 風向は「どこから吹くか」。`u`/`v` から出すときは `(270 - θ) % 360`（`(450 - θ)` は「どこへ吹くか」で 180°ずれる）。
- `CloudGridLayer` と格子インデックス計算は共有しますが、**共通の基底クラスにはまとめない。**雲はデータがあるとき `putImageData` が全面を上書きするのでクリア不要、風は矢印を `stroke` するので毎タイル先にクリアが必須、とクリアの順序が意図的に違うためです。

## 降水・雷ナウキャスト（`nowcast.js` / `app.js`）

データ側の落とし穴（偶数ズーム・8色・`thns` の z10 など）は [data-sources.md](data-sources.md) を正とする。ここでは UI と配線の要点だけ書く。

- 雲・風と時間軸が違うので、時刻コントロールは地図下でタブに応じて**中身ごと入れ替える**（同時に2つ見えるとどれが効いているか分からなくなる）。表の赤枠は雲・風のプルダウン時刻に連動したまま。
- 降水の実況は API 上は過去3時間あるが、表示は直近1時間に絞っている（ラベル密度と再生時の取得枚数のため。`OBSERVED_MINUTES`）。
- タイムラインの UI（スクロール・スナップ・再生・リセット・レイアウト）は降水・雷で共有 DOM を使う。**`createTimeline` の `activate` / `deactivate` で、表示中のタブだけがリスナーを持つ。**両方に常時貼ると再生ボタンが二重に動き、裏タブが時刻表示を奪い合う。
- 再生中は `onScroll` を無視する。再生自身がスクロール位置を管理しているのに、負荷でスナップ用タイマーが間に合わないと「行ったり来たり」が起きるため。
- 端のコマを中央に来るための余白は、`.nowcast-strip` の `padding` では作れない（絶対配置の子は padding box 基準のため目盛りが動かない）。目盛り層の `left` でずらす。
- タイムラインを黒地にしているのは、気象庁の降水色が黒地前提で、白地だと弱い雨（`#f2f2ff`）がほぼ見えないため。雲・風の操作部は白のままにし、黒地自体を「ナウキャスト操作に切り替わった」合図にもしている。
- Service Worker は `jma.go.jp` をキャッシュしない。ナウキャスト URL に時刻が入るため再利用できず、地形タイルの枠を食い潰す。

## 地点の予測（`weather.js`）

- Open-Meteo の API を**1リクエスト**で呼び、MSM と AIFS をまとめて取得します（16日分・約58KB）。
- MSM は1時間ごと。雲量の地図と範囲をそろえるため、地図の基準時刻より前の列は落とします（`trimSeriesBefore`）。
- AIFS は6時間ごとの計算なので、日本時間の 3/9/15/21時だけを表示します。API が1時間ごとに補間した値は使いません。
- 気温は API の既定（地点の実標高に合わせた値）です。生の格子値が欲しい場合は `elevation=nan` を付けます。
- 週間予報は、国土地理院の逆ジオコーダで市区町村コードを得て、気象庁の `area.json` の親子関係（class20 → class15 → class10 → office）で府県予報区を特定します。
- 気象庁の class20 のコードは市区町村コードそのままとは限りません。政令指定都市は市単位（大阪市 `2710000`）だったり、市を独自に分割していたり（横浜市北部 `1410011`）します。`findClass20()` が「完全一致 → 政令指定都市の区に限り市コードで前方一致」の順に解決します。
- `area.json` は200KB近いので `loadJmaAreas()` で一度だけ読み、地名の解決と週間予報で共有します。
- `reverseGeocodeAddress()` は緯度経度を「東京都千代田区」にします。政令指定都市は区まで出ず市止まり（気象庁側に区が無いため）、海上・国外・境界未定地域では `null` を返します。
- 天気コードとアイコンのファイル名は一致しません（118コード中88コードが別名）。`WEATHER_TELOPS` に対応表を持っています。

## 表の作り方（`app.js`）

- 行が項目、列が時刻。左端の項目名は `position: sticky` で固定し、枠線は「セルの右と下」に引いています（`border-collapse: collapse` だと固定列の左右の線が流れるため）。
- 日付の行は同じ日をまとめた1セルで、中のラベルを `position: sticky` にして次の日まで追従させます。
- 過ぎた時間帯のセルには `.past` を付け、背景色を消して文字を薄くします。判定は「そのセルの時間帯が終わったか」で、1分ごとに付け直します。
- 雲量の地図で選んでいる時刻の列は、1時間予測の表だけ赤枠で囲み、画面外ならその列までスクロールします。
- 色分けの関数は `cloudCell` / `rainCell` / `humidityCell` / `temperatureCell` / `pressureCells`。しきい値はそれぞれの関数の先頭にまとまっています。
- 雲量の色は地図と逆向きです（地図は黒地に白、表は白地に灰色）。区切りは同じで、下地の明暗が違うので意図的に分けています。
- 気圧は `PRESSURE_RULES`（6時間で±2/4/6hPa、24時間で±5/8/12hPa）の**強いほう**を採用します。

## 地点ピン（`pin.js`）

- PC はクリック、スマホは長押し（500ms、指が10px以上動いたら取り消し）でピンを置きます。Leaflet の `contextmenu` はスマホで発火しないため、`pointerdown` から自前で判定しています。
- ピンは7枚の地図すべてに置き、ドラッグ中も他の地図が追従します。
- ピンはドラッグ可能です。地図 click でもピンを置くため、マーカー click と衝突しやすいです。マーカーは `bubblingMouseEvents: false` にし、それでもタイルへ抜けた click は座標ヒットで「置く」を抑止してメニューへ回します。
- 現在地は `navigator.geolocation`。ボタンから呼べるほか、パラメータの無い URL で開いたときは自動で取得します。自動のときは断られても何も表示しません（ユーザーが頼んだ操作ではないため）。「パラメータが無いか」の判定は、`updateUrl()` が `lat`/`lng`/`z` を書き込む前に確定させておく必要があります。
- 現在地のピンだけ、表示名を逆ジオコーディングで市区町村にします。`rename()` は座標を変えないので、名前の差し替えで予測を取り直すことはありません。クリックや長押しで置いたピンは緯度経度のままです。
- 場所検索は国土地理院の住所検索 API をブラウザから直接呼びます（CORS 許可あり）。地図の中心から近い順に並べ、都道府県は `addressCode` の先頭2桁から付けます。
- 緯度経度の読み取り（十進・度分秒・N/S/E/W・全角・順序の自動判定）は xLineMap（同じ作者）の実装を移植したものです。

## 保存地点（`places.js`）

- 保存先はブラウザの `localStorage`（キー `ccf-places`）。サーバーには送らず、この端末のこのブラウザだけに残ります。
- 値は `{ id, lat, lng, name }` の配列。一覧 UI は持たず、各地図に水色（`#00acc1`）の小さめの丸を配るだけです（`PinController` と同様、7枚それぞれに `L.layerGroup`）。
- 丸をタップすると、その地点に赤ピンを立てて地図を中心化し、編集・削除のメニューを出します。赤ピン側のメニューは未保存なら登録、同じ座標に保存済みなら編集・削除です。
- 同じ地点の判定は緯度経度を小数第5位で丸めた一致（おおよそ1m）。一致すれば新規追加せず名前を上書きします。赤ピンと同じ座標の保存丸は重ねて出さないように隠します。
- 削除前に `confirm` で確認します。読み書きは try/catch で囲み、失敗しても画面は壊しません。
- **一覧が無いので、画面外の保存地点には飛べない**（仕様として受け入れ）。運用で不便ならそのとき考える。

## フルスクリーン（`app.js` / `styles.css`）

- `.maps-panel` に `is-fullscreen` を付け、タブ＋地図＋時刻＋地点行を `position: fixed; inset: 0` で広げます。予測表は後ろに隠れてよい、という仕様です。
- トグルは各地図右下の Leaflet コントロール（四隅枠 ⇔ 内側矢印）。Esc でも閉じます。
- スマホの「雲(上中下層)」は全画面時だけ1層表示にし、地図上のフロートで上／中／下を切り替えます（`data-layer`）。PC（幅1000px以上）は横三分割のまま縦だけ広げます。
- 出入りのあと `invalidateSize()` を呼びます（タブ切替と同じ理由で、隠れていた地図の大きさを測り直すため）。

## 画面まわりの方針

- 幅を決めているのは雲量の地図だけです。ヘッダー・フッター・表は画面の横幅いっぱいを使います。
- 初期表示は関東の緯度経度の範囲に `fitBounds` で合わせます。`zoomSnap: 0.25` の小数ズームで、地図の大きさが変わっても表示範囲を保ちます。
- スマホは全雲量の1枚、PC（幅1000px以上）は3枚が既定です。スマホで1時間予測の表までファーストビューに入れるためです。
- フッターは `min-height: 100dvh` と `flex: 1 0 auto` で画面下に固定します。
- タブの見た目はジャンル分けしています。雲量・風（モデル）は青い太線、降水・雷（ナウキャスト）は斜めカット＋タリーランプ風の赤グラデーション上線です。表の見出し色（予測／予報）と揃える必要はない、という意味では意図的に離しています。
- タブの並び（雲・風が連続し、その右に降水・雷）は変えない。ジャンルが2群として読める前提です。

## ローカルでの動かし方

```bash
python3 -m http.server 8765
```

`http://localhost:8765/index.html` を開きます。`?pin=35.85558,138.94393&pinname=雲取山` を付けると、ピンのある状態をすぐ確認できます。

モジュールはブラウザにキャッシュされるため、`.js` を編集しても反映されないことがあります。その場合はスーパーリロード（Cmd+Shift+R）してください。

**Service Worker:** ファイルを追加・改名したときは `sw.js` の `VERSION` を上げる。古いシェルが残っていると、新規ファイルが 404 ではなく `ERR_FAILED` で落ち、画面が真っさらに見えることがある。実機確認の前に一度リロードが要る。

- 雲量の地図を、GitHub Actions で `.om` を uint8 バイナリに変換して Pages に置く方式へ切り替えられる構造にしてあります（描画側は「格子の定義＋層ごとの `Uint8Array`」しか受け取りません）。ブラウザから WASM と GPL のコードを外せます。
