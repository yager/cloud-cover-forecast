## モデルの仕様

| モデル | 解像度 | 先まで | 刻み | 備考 |
|---|---|---|---|---|
| 気象庁MSM | 5km（0.0625°×0.05°） | 78時間（00/12UTC）、他は39時間 | 1時間 | 日本周辺のみ |
| ECMWF AIFS | 0.25°（約25km） | 15日 | 6時間 | ECMWF の AI モデル。2025年2月から正式運用 |
| 気象庁GSM（未使用） | 無料公開版は0.5°（約55km） | 11日 | 6時間 | 山では粗すぎるため採用せず |

**配信の遅れ**: MSM は初期時刻から3.5〜5時間、AIFS は約5.6時間（実測）。

**1コマのデータ量**: MSM は全要素で約800KB。全球モデルは1コマが GSM 8MB、AIFS 29MB あるため、面データとしては現実的ではありません（地点の時系列なら範囲指定で1変数1KB程度）。

## 気象業務法の整理

気象庁の[予報業務許可のFAQ](https://www.jma.go.jp/jma/kishou/minkan/q_a_o.html)より。

- 数値予報モデルの格子点値をそのまま表示すること自体は、予報業務の許可なしでできる。
- 「予報業務を行っていると誤解されないために、予報ではなく数値計算の結果であり、大きな誤差が含まれる可能性があること等を明示することを**推奨**」（義務ではなく、表示場所や回数の決まりもない）。
- **「予報と称して提供、表示する場合には独自の予報とみなされます」**。呼び方が決定的。
- **空間内挿や地形による補正等の加工**を行うと、独自の予報とみなされる可能性がある。

このサイトでの対応:

- モデルの計算値は「予測」、気象庁の発表は「予報」と呼び分ける。
- 格子は最近傍で塗り、補間・平滑化をしない。3層を合成した独自の指標（「星が見えるか」など）は作らない。
- 注意書きはフッターに1か所、各表の「ⓘ」に短く。
- 気温は Open-Meteo の API が地点の標高に合わせて補正した値を表示している。補正はデータ提供元が行っているもので、このサイト側では加工していない。何の値かを ⓘ に明記してある。生の格子値に戻す場合は `elevation=nan` を付ける。

## 検証の記録

**雲量タイルとの一致**（2026-09-21）

- ウェザーニューズの雲量タイルの中身は MSM の層別雲量そのもの。bounds がMSM格子の半マス外側と一致し、地点値も一致。
- ブラウザで描いた `CloudGridLayer` のタイルと、同じ時刻・同じ z5 タイルを画素単位で比較して RGBA 完全一致が 98.8〜99.9%。不一致の約97%は色の境目から2px以内（1マスが約3px）。
- 格子を半マスずらすと一致率が 89〜97% に落ちるため、格子の位置合わせは正しい。

**地点値の一致**

- 全国7地点の下層/中層/上層の雲量が、Open-Meteo API の値と完全一致（行0が南端、緯度 22.4+0.05·iy、経度 120+0.0625·ix）。

**天気コードとアイコン**

- 気象庁の天気コードとアイコンのファイル名は一致しない（118コード中88コードが別名。例: 211「曇後晴」→ `210.svg`）。対応表は気象庁の天気予報ページが持つ `TELOPS` から書き起こし、アイコン30種類すべての存在を確認済み。

**AIFS の降水量**

- API の1時間値は6時間ブロック内で同じ値が並ぶ。S3 の6時間合計とほぼ一致するため、**6時間の合計を1時間あたりに直した値**。表示はそのままでよく、割る必要はない。

**気圧痛のしきい値**

- 医学的な報告: 前日比で5hPa以上の低下があると頭痛が増える。標準の1013hPaから6〜10hPa低い1003〜1007hPaが悪化しやすい帯。
- 頭痛ーる・ウェザーニュースとも、具体的なしきい値は非公開。
- 実測（MSM、5地点・4日分）では、3時間で±3hPa以上動く時間は0〜2%しかなく、窓が短すぎると色が付かない。6時間で±2hPa、24時間で±5hPa を弱の基準にすると、穏やかな時期でも2〜3割の時間に「弱」が出て、中・強は荒天時だけに出る。

**気象庁のナウキャスト系タイル**（2026-09-25）

気象庁ホームページが使っているエンドポイント。公式に文書化されてはいないが、認証なしで CORS も通る（実際に取得して確認）。現象が無い区画は334バイトの透明PNGが返る。

| データ | 時刻一覧 | 範囲 |
|---|---|---|
| 高解像度降水ナウキャスト | `nowc/targetTimes_N1.json`（実況）、`_N2.json`（予測） | 過去3時間〜+1時間、5分刻み |
| 降水短時間予報 | `rasrf/targetTimes.json` | +15時間、1時間刻み |
| 雷・竜巻ナウキャスト | `nowc/targetTimes_N3.json` | 過去1時間〜+1時間 |
| 降雪・積雪 | `snow/targetTimes.json` | 過去24時間〜**+6時間** |
| 天気分布予報 | `wdist/targetTimes.json` | 降水・降雪・気温・天気（**風は無い**） |
| ひまわり衛星画像 | `himawari/data/satimg/targetTimes_jp.json` | 過去1.5日、2.5分刻み |

- タイルは `jmatile/data/{種別}/{basetime}/none/{validtime}/surf/{要素}/{z}/{x}/{y}.png`。
- 衛星は `himawari/data/satimg/{basetime}/{jp|fd}/{validtime}/{B13/TBB|B03/ALBD|REP/ETC|SND/ETC}/{z}/{x}/{y}.jpg`。
- **点データはタイルではない。**落雷の実況 `liden` は `.../surf/liden/data.geojson?id=liden` で全域1本の GeoJSON として返る（`application/geo+json`）。`.png` を探しても見つからない。
- **`liden` は累積ではなく、その5分間に発生した新規の点だけを返す。**同じ `basetime`/`validtime` を後から取り直しても増えない（実況の過去コマは固定）。`properties` は `{id, obstimeJST, type}`。日本で実際に発雷していた時間帯（2026-09-25 沖縄付近）に取得して確認した。`type` は取得できた範囲では常に `4` で、意味は未確認（気象庁のページはCG/CC・経過時間で色分けしているが、対応する定義は取れなかった）。
- **`thns`（雷ナウキャスト）は予測だけではない。**`basetime == validtime` の時刻は落雷観測とレーダーから求めた実況で、`validtime > basetime` が予測。`thns` は10分刻み、`liden` は5分刻みで、同じ時刻一覧（`targetTimes_N3.json`）の中に混在する。
- **`thns` は同じ地点・同じコマでもズームによって着色の有無が入れ替わることがある。**実測で、ある地点のあるコマがズーム10（一番細かい）では空、ズーム8では着色、ということがあった。1kmメッシュのデータをズームごとに別々に描画しているためとみられる。地点の値を読むときは、細かい方（10→8→6→4）から順に試して最初に見つかったズームを使う（`nowcast.js` の `sampleThunderAt`）。**「発雷していても空タイルのことがある」という当初の説明（面として計上される閾値の話）は推測であり、確認できていない。**
- **雷の活動度1〜4の色は、気象庁の解説ページ「雷ナウキャストの見方」**（https://www.jma.go.jp/jma/kishou/know/toppuu/thunder2-2.html）**の「活動度と行動の対応」表の画像から実測した。** 活動度1=`#faf500`（黄・雷可能性あり）、2=`#ffaa00`（橙・雷あり）、3=`#ff2800`（赤・やや激しい雷）、4=`#c800ff`（紫・激しい雷）。活動度1の色は実際のタイルでも同じ値を確認済み。2〜4は解説ページの図からの値で、タイルでの一致は未確認。
- **ナウキャストのタイルは偶数ズームにしか中身がない（z4 / z6 / z8 / z10）。**奇数ズームや z11 以上は 404 ではなく **HTTP 200 で334バイトの完全透明 PNG** を返すため、応答コードでは気付けない。雨のある領域の z7 タイルを30枚走査して全て透明、同じ領域の z8 は3万px以上という形で実測した（実況・予測のどのコマでも同じ）。Leaflet のタイルズームは `Math.round(地図のズーム)` なので、対策しないと地図が z7.25 になった瞬間にレイヤーが消える。
- **降水のタイルは8色ちょうどで、中間色が無い。**弱い順に `#f2f2ff` `#a0d2ff` `#218cff` `#0041ff` `#faf500` `#ff9900` `#ff2800` `#b40068`。日本全域 × 先15時間ぶんのタイルを走査して出てくる色を数えて確かめた（出現面積は弱い色ほど大きく、順序とも整合する）。中間色が無いので、**地点の画素の色から強さの階級を引き戻せる**。タイルを `fetch` → `Blob` → `createImageBitmap` の順で読めば canvas が汚染されないので、`crossOrigin` を付けなくても画素を読める。**各階級の mm/h 境界は気象庁のナウキャスト表示ページ**（https://www.jma.go.jp/bosai/nowc/ 、凡例パネル）**で確認した**: 弱い順に 1・5・10・20・30・50・80 mm/h（最弱は1未満、最強は80以上）。
- **`snowf72h` の「72時間」は積算期間**であって予報の先読みではない。このタイルの予報は +6時間まで。
- 時刻一覧の `basetime` / `validtime` は **UTC**（最新コマと現在時刻の差を実測して確認。JSTとして読むと9時間ずれる）。

**`.om` ファイルに入っている要素**（2026-09-25）

雲量のために毎コマ取得している MSM の `.om`（約950KB）には、雲量以外も同じ 505×481 の格子で入っている。読み足しても通信量は増えない。

```
cloud_cover / cloud_cover_low / cloud_cover_mid / cloud_cover_high
wind_u_component_10m / wind_v_component_10m
temperature_2m / relative_humidity_2m / precipitation / pressure_msl
shortwave_radiation
```

Open-Meteo の API 側には MSM の `snowfall`（cm）もあるが、`snow_depth` は配信されていない（値が null）。

**週間予報の空欄**

- 気象庁の週間予報は、先頭の日だけ天気コード以外が空で配信される（その日は3日先までの予報が受け持つため）。信頼度は3日目以降にしか付かない。仕様どおりなので、そのまま「−」で表示している。
